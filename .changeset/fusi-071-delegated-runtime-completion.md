summary: Fix cursor-cli tasks failing after a successful run by honoring the CLI runtime's own completion signal.
category: fix
dev: Delegated CLI plugin runtimes (cursor/droid/grok) never call Fusion's injected `fn_task_done` tool — they run their own self-contained agentic loop. `packages/engine/src/runtime-resolution.ts` adds `isDelegatedCliRuntime(runtimeId)` (true for any resolved runtimeId that isn't the default pi runtime or the mock provider). The executor completion gate (`executor.ts`) now treats a delegated runtime's terminal-success (`promptWithFallback` resolving without throwing) as implicit `fn_task_done` on the FIRST session, so the "Agent finished without calling fn_task_done — retrying with new session" loop is never entered for a successful cursor-cli/droid/grok run; a terminal-error still flows through the existing failure handling unchanged (never a silent retry). `pi.ts`'s `promptWithFallback` now threads the runtime's `AgentPromptResult` (including `usage`) through instead of discarding it, and the executor captures that usage into `task.tokenUsage` via a new `applyDelegatedRuntimeUsage()` helper (these sessions don't implement `getSessionStats()`, so the existing baseline-diff token-usage seam was a no-op for them). `createResolvedAgentSession` also attaches the resolved runtime's own `describeModel` on the session for non-default runtimes, fixing the cosmetic `Executor using model: undefined/undefined` log line (now reports e.g. `cursor/auto`). pi/Claude/mock sessions are unaffected — regression-guarded by new tests in `runtime-resolution.test.ts`, `pi.test.ts`, `agent-session-helpers.test.ts`, and the new symptom-based `executor-delegated-runtime-completion.test.ts`.
