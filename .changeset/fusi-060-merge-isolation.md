summary: Merger now refuses (never autostashes) an unmerged-index target checkout and force-cleans conflict stage after aborts.
category: fix
dev: Closes the 2026-07-11 incident where the auto-merger left the operator's primary checkout with UU/AA unmerged-stage index entries and no MERGE_HEAD (`git merge --abort` had nothing to abort; `git stash` refused with "unmerged paths"). Two coupled fixes in `packages/engine/src/merger-integration-worktree.ts` and `packages/engine/src/merger.ts`: (1) merge isolation — the `worktree-equals-project-root` refusal (`MergeHandoffRefusedError("reuse-misconfigured", "worktree-equals-project-root", …)`) now also guards `advanceIntegrationBranchRef` (`packages/engine/src/merger-ref-update-advance.ts`, new `requireIsolatedRoot` opt-in wired from the isolated reuse-task-worktree ref-advance call site) so a ref advance can never run `git update-ref` against the primary checkout; (2) a new `classifyTargetCheckoutState` helper (reused across `acquireReuseHandoff` and the pre-merge `stashUnrelatedRootDirChanges` gate in `aiMergeTask`) classifies the target checkout as clean / dirty-autostashable / unmerged-index / unsafe-dirty via `git status -z --porcelain`, and refuses fail-soft (`MergeHandoffRefusedError`/parked task + new audit events `merge:integration-root-unmerged-index-refused` and `merge:integration-root-unsafe-dirty-refused`) instead of autostashing an unmerged index. A new `assertConflictStageCleaned` invariant (wired into `resetMergeWithWarn`, the cherry-pick cleanup invariant, and a post-failure finalize safety net) verifies zero unmerged index entries and no MERGE_HEAD-less conflict stage remain after any abort/failure/cleanup, force-completing a scoped `git reset --hard` + `git clean -fd` in the isolated worktree only when needed, and emits `merge:conflict-stage-cleaned`. Regression coverage: `packages/engine/src/__tests__/reliability-interactions/merge-isolation-guard.real-git.test.ts` (new, real-git) plus extended unit coverage in `merger-integration-worktree.test.ts`.
