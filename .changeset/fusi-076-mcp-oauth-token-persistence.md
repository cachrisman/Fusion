summary: MCP OAuth token refreshes now persist to secrets across restarts for the AI-session and validation lanes.
category: feature
dev: Adds `packages/core/src/mcp-oauth-persistence.ts` (`updateMcpServerOAuthTokens` / `saveMcpServerOAuthClientInformation`), an engine-free, scope-aware settings-mutation API that idempotently creates/updates the backing Fusion secret(s) and rewrites the matching stored `McpServerDefinition.auth` block's secret refs + `expiresAt` in the scope (project vs global) that owns the server, fail-soft no-op when the server is concurrently deleted/renamed. `packages/engine/src/mcp-oauth-provider.ts` adds `createSettingsBackedMcpOAuthTokenStore`, a real `McpOAuthTokenStore` implementation replacing FUSI-074's warn-only stub, built by `packages/engine/src/mcp-resolution.ts`'s `buildMcpOAuthTokenStore` (+ additive `scopeByServerName` addressing map). This is now wired into all real (non-test) call sites reachable in this task's scope: `createFnAgent` (`packages/engine/src/pi.ts`, via new `mcpOAuthTokenStore`/`mcpSettingsStore`/`mcpServerScopeByName` options) and both dashboard MCP paths in `packages/dashboard/src/routes.ts` (`POST /api/mcp/validate` and the manual AI-prompt workflow-step lane). AI lanes that resolve MCP servers via `resolveMcpServersForStore` but do not yet thread a settings store through session creation (executor/merger/reviewer/triage/evaluator/etc.) still fall back to the FUSI-074 warn-only no-op for now — persisted writeback there is tracked as follow-up work. Never logs token/refresh-token/client-secret material.
