### Medium — `fn_workflow_lint` is not a full create preflight
The FNXC comment says it wraps the **same** validators the store runs, but `createWorkflowDefinition` also runs `assertWorkflowIrTraitsValid` (column trait conflicts), and `fn_workflow_create` runs `assertWorkflowColumnAgentBindings` before persist. Neither is called in `fn_workflow_lint`.

A client can get `valid: true, runnable: true` from lint and still have `fn_workflow_create` reject on trait composition or column-agent policy escalation.

---

### Medium — invalid IR is returned as a non-error MCP result
Parse failures use `textResult(...)` without `isError: true`, while missing `ir` uses `errorResult(...)`. Clients that key off `isError` (common MCP pattern) will treat malformed IR as a successful tool call; only `structuredContent.valid: false` signals failure.

### Medium — `runnable` overstates blocking behavior
`runnable` is `warnings.length === 0` for non-fragments, but lifecycle warnings are advisory in core/store — create/update **still persist** workflows with warnings (`lifecycleWarnings` is stored, not a hard gate). An agent may treat `runnable: false` as “cannot ship,” or conversely assume lint green means dispatch-safe; neither matches store behavior. The tool description partially mitigates this (“first-order verdict”), but the field name is strong.
